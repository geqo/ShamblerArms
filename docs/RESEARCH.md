## 2. NonUnoPinata (avilmask.NonUnoPinata)

- Последний коммит 2025-08-07 (1.3.3), поддержка до **1.6**, сборки под 1.7 нет.
- **Лицензии в репо нет** → по умолчанию все права у автора. Код копировать нельзя, логику
  можно реализовать самим.
- Workshop: 1778821244, локально **не установлен**.

### Как он работает (исходники `source/PawnIsNotPinata16/Patches/`)

| Патч | Что делает |
|---|---|
| `Pawn.Kill` (transpiler) | меняет вызов `DropAndForbidEverything` на свой `DropOnKill` |
| `Pawn_HealthTracker.MakeDowned` (transpiler) | то же для падения → `DropOnDown` |
| `DropThings` | всегда выкидывает то, что пешка несёт в руках (carryTracker); оружие и инвентарь выкидывает только если так включено в настройках (по 4 флага: свой/чужой × убит/упал). Ванильный дроп оставлен для `destroyGearOnDrop`, пешки в контейнере, не заспавненной пешки и пешки в кровати |
| `Pawn_EquipmentTracker.Notify_PawnSpawned` (transpiler) | не выкидывать оружие у лежачего при спавне |
| `Pawn.Strip` (prefix) | если на пешке есть помеченные вещи — снимает только их |
| `CompStripChecker` | комп, который добавляется вещам на лету: флаг «снять эту вещь» + сохранение |
| Стартап | всем `Item` с `thingClass == Thing` меняет класс на `ThingWithComps`, чтобы на них вешался комп (это грубо и влияет на все предметы) |
| `ITab_Pawn_Gear.DrawThingRow` | кнопка «снять» у каждой вещи во вкладке снаряжения |
| `JobDriver_Strip`, `Designation.Notify_Removing` | порядок «сначала снять, потом убрать обозначение» |
| `Toils_Recipe.CalculateIngredients` | правила раздевания при кремации/разделке |
| `GenDrop.TryDropSpawn` | сбрасывает флаг у выпавшей вещи |
| Ideology-дуэль | XML-патч + свой duty/job: эскорт снимает оружие с упавшего дуэлянта (ваниль рассчитывает, что оно выпало само) |
| Совместимость | RPG Style Inventory, Awesome Inventory |
| Отключено автором | показ оружия на трупе (рендер переделали в 1.5), Multiplayer |

### Вывод: зависимость или своя логика

Зависимость брать **не стоит**: нет лицензии, нет 1.7, автор неактивен, плюс глобальная
подмена `thingClass`. Делаем своё ядро «не-дропа» и **выключаемся, если NUP активен**:

```csharp
static bool Prepare() => !ModsConfig.IsActive("avilmask.NonUnoPinata");
```

Минимум для нашего ядра: Kill/MakeDowned/Notify_PawnSpawned + дуэль. Раздевание есть
и в ванили: ванильный `Strip` снимает всё сразу, так что поштучное снятие делаем на
втором этапе (или не делаем вовсе).

**Важно для шамблеров:** когда NUP активен, оружие остаётся на трупе благодаря NUP, но
шамблерную часть (п. 3) мы держим всегда включённой: NUP её не покрывает.

## 3. Почему шамблеры не используют оружие (цепочка ограничений)

1. **Смерть:** `Pawn.Kill` → `DropAndForbidEverything`: у трупа оружия уже нет. Это закрывается п. 2.
2. **Поднятие:** `Pawn_MutantTracker.Turn()` → `HandleEquipment()` **всегда выкидывает
   `equipment.Primary`**. Нужен prefix или transpiler (зависит от настройки интеллекта).
3. **Шамблеры, заспавненные готовыми** (рейды, death pall): `MutantUtility.SetFreshPawnAsMutant`
   **уничтожает** `Primary`. Нужен патч: оставлять оружие (или выдавать по уровню интеллекта).
4. **XML** `BaseMutantEntity.workDisables: AllWork, Shooting`. В коде `Shooting` проверяется
   только при надевании/подборе/генерации оружия (`FloatMenuOptionProvider_Equip`,
   `JobGiver_PickUpOpportunisticWeapon`, `PawnWeaponGenerator`, outfit stand). Если оружие
   уже в руках, этот флаг атаку не блокирует. Но навык «Стрельба» считается отключённым → уровень 0.
5. **AI:** `JobGiver_ShamblerFight.TryFindShootingPosition` → всегда `false`. В
   `JobGiver_AIFightEnemy.TryGiveJob` с дальним verb'ом это значит: стреляет только если цель
   ближе 5 клеток (или шамблер уже за укрытием); иначе — `null`, и шамблер просто бродит.
   Нужен патч, который вызывает базовый поиск позиции.
6. **Ближний бой:** `Pawn_MeleeVerbs` для мутантов verb'ы экипировки **не исключает**, так что
   оставленное холодное оружие должно работать сразу. Проверить в игре.
7. Прочее: `DisableAbilityVerbs = true`, `canBeDrafted = false` (своих не задрафтить),
   `MeleeCooldownFactor ×1.5` из хедиффа. Своих шамблеров `Verb.CausesTimeSlowdown` не замедляет.
8. Хуки для модов: в ThinkTree шамблера есть `insertTag` `Shambler_PreMain` и `Shambler_PreWander`.
   Через них можно добавить подбор оружия (`JobGiver_PickUpOpportunisticWeapon`) без Harmony.

## 4. «Интеллект» шамблера

Сознание у шамблеров **есть**: это пешка с хедиффом `Shambler` (`Hediff_Shambler`), и хедифф
даёт `Consciousness postFactor 0.7`, `Talking 0`. Значит, рычаг «уровень сознания» работает
и на них. Сознание влияет на Manipulation/Sight → точность стрельбы и ближний бой.

Предлагаемая модель (на обсуждение):

- Настройка мода «интеллект шамблеров» 0–100 % (глобально, можно с разбросом на каждого).
- На поднятии вешаем свой хедифф `ShamblerIntellect` с severity = интеллект. Его стадии:
  - **0** — ваниль: оружие выкидывается;
  - **низкий** — оставляет только холодное оружие;
  - **средний** — стреляет, но только вблизи (ванильное поведение п. 5, позицию не ищет);
  - **высокий** — ищет позицию для стрельбы (снимаем запрет п. 5), подбирает оружие.
- Severity также масштабирует сознание (capMod) и даёт уровень навыка «Стрельба» из прежнего
  навыка пешки (×интеллект). Для этого шамблерам надо обойти `TotallyDisabled` у Shooting.
- Плюс: состояние видно во вкладке здоровья, сохраняется само, можно править XML-патчами.

## 5. Решения (2026-11-04)

1. Сначала под **1.6**, 1.7 потом отдельной папкой.
2. Не выпадает и у мёртвых, и у упавших; у всех фракций.
3. Раздевание ванильное, поштучного нет.
4. Интеллект: глобальный уровень + разброс.
5. Оружие не выдаётся. Только шамблеры, поднятые из вооружённых пешек; тактики подбирают
   оружие по пути.

Ещё одна находка при реализации: шамблеры в рое (duty `ShamblerSwarm`) до тега
`Shambler_PreMain` не доходят, поэтому подбор оружия вставлен в эту duty отдельным XML-патчем.

## 6. Что проверить при переходе на 1.7

- `Pawn_MutantTracker.HandleEquipment` повторяет ванильную обработку одежды 1.6. Сверить с 1.7.
- `Pawn_EquipmentTracker.Notify_PawnSpawned` пропускается целиком: в 1.6 он только роняет оружие.
- Harmony 3 строже проверяет типы `__instance`/`__result`/`___field`.
